# Session Handoff - 2026-08-04 (Sprint 1.4 Implementation)

## Session Summary

**Objective:** Implement Issue S1.4 — Supervisor Kernel (the Core): the orchestration logic that moves a job through the recipe DAG.

**Method:** Sequential (files are interdependent). Built `@fyi/supervisor` with kernel, step-runner, queue handlers, config, and a shared bootstrap, then verified with an integration test that drives the full pipeline (3 workers + supervisor).

**Outcome:** S1.4 completed. The Supervisor moves a job from PENDING through research → script → voice to COMPLETED, merges artifacts, writes telemetry, and honors approval gates. Integration test passes consistently.

---

## Decisions Made

- **Contracts v1.1 authoritative:** NOT the outdated Issue-004 draft (which used a `WorkerCapability` enum, `RESEARCHING/SCRIPTING/VOICING` statuses not in JobStatus v1.1, `@fyi/utils/redis` path). Implemented with `capability: string`, `JobStatus` (PENDING/RUNNING/WAITING_APPROVAL/COMPLETED/FAILED), full `TaskEnvelope` (tenant_id, policy, context, references, attempt).
- **Single-writer step chaining:** The poll loop dispatches **only PENDING** jobs. Once a job is RUNNING, subsequent steps are chained exclusively by `StepRunner.onStepSucceeded` (completion worker). This eliminates double-dispatch races (initial impl dispatched the same step from both poll loop and completion callback, causing out-of-order artifact merges).
- **Step identity:** `WorkerResponse` v1.1 has no `step_id`, so the completing step is derived from `job.current_step_index`.
- **Artifacts shape:** each step's output stored under `artifacts[step.id]`; new_references merged under `artifacts._references`. Matches supervisor-design.md §10.
- **input_mapping resolution:** dot-notation paths (e.g. `research.research_brief`) resolved against `artifacts` via `lookupPath`.
- **Shared bootstrap** (`bootstrap.ts`) used by both the entrypoint and the integration test, so the completion worker + kernel are wired identically.
- **Telemetry provider/model:** hardcoded `mock`/`mock-model` (MVP; worker response does not carry provider/model).
